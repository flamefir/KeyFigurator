## 2026-07-27 · OLED image + GIF screens (protocol v2) · #firmware #config-app #oled #protocol
What: Image and animated-GIF OLED screens, end to end. The old objection ("1000+ reports per frame") only applied to *streaming* — the image is uploaded ONCE as a Quantum Painter QGF and animated on-device by `qp_animate`, so there is zero per-frame traffic and the animation survives the app closing. New `qgf.rs` is a from-scratch QGF encoder (the board has no PNG/GIF decoder and QGF is the only container Quantum Painter reads), reimplementing what `qmk painter-convert-graphics` does because the app cannot depend on the user having a Python toolchain: PALETTE_4BPP uncompressed, one shared palette quantised across all frames so flat colours don't shimmer, GIF frames sampled evenly to 8 with delays merged so total duration is preserved, and oversized input scaled rather than rejected. Firmware side is a 3-command upload (`0x55`-`0x57`, offset-addressed so a dropped chunk can be re-sent) into a single 72 KB buffer, with the byte count verified before `qp_load_image_mem` so a short upload can never load a truncated image. A custom screen that has an image becomes an IMAGE screen on the wire, reusing the existing upload UI. Uploads are cached against the data URL because live sync would otherwise re-send tens of KB on every keystroke. 45 Rust tests pass (11 new, including bit-packing order and a real-QGF-through-the-transport integration test); firmware builds clean at 95 KB RAM of 264 KB.
Refs: keyfigurator/src-tauri/src/{qgf.rs (new), kf_protocol.rs, hid.rs, main.rs, Cargo.toml}, keyfigurator/src/main.js; firmware keyboards/macro_pad_pro/{kf_hid.h, kf_hid.c, display.{h,c}, readme.md}.

## 2026-07-28 · Device identity, home page, macro libraries, pilot fixes · #config-app #firmware #protocol #ux
What: Turned the app from a single-board editor into a device manager, off the back of a pilot session. Identity is now three independent layers — `GET_IDENTITY` (`0x02`) reports product id + hardware revision + firmware build, and a static `products.rs` table says what each product+hardware can actually do. **Capabilities belong to hardware, never firmware**: no update can add an encoder push that was never soldered, and rev 1.0.0 has none, so the table names key index 5 as the stand-in "Special Enter". New home page lists devices (connection state, versions, transport icon, delete) with a New Device scan; the editor is entered by picking one, so it always runs against a known revision. Macro libraries browse like folders — tiles at the top level, macros inside — in a versioned, shareable format; a macro is either keystrokes (`MACRO(n)`, board-executed) or a **shell script** (`HOST(n)`, run by `runner.rs`) authored in a terminal-style editor, which let the separate HOST BINDINGS UI be deleted rather than merely moved. Macros bind to keys from key Advanced settings, with slots derived (never stored) so keycodes and allocation cannot drift apart.
Fixes from piloting: countdown starts 00:00:00 (and refuses to start a zero timer); the OLED's "USB" label became a real green/red app-link dot driven by a frame heartbeat, since a cable says nothing about the app being open; Present Keys shows the key you physically press; encoder rotate buttons overhung 5px into a 6px grid gap at z-index 5 and were swallowing clicks meant for the key below; window minWidth was 420 against a layout that needs ~940.
**Persistence audit — it was not true**: `keyLedColors`, icons and keymap only ever saved through a path that returned early without an active layer, so on a fresh install every colour, icon and keycode edit was lost on restart; even with a layer, saves ran only on layer switch; and every setting shared one global key, so two boards overwrote each other. Now one auto-saved blob per device, hooked into `scheduleLiveSync` so a new mutation point cannot sync-but-not-persist, flushed on exit and on window close. 53 Rust tests pass.

## 2026-07-29 · Present Keys rework, per-screen LEDs, image icons, font scale, LED alerts, first release · #config-app #firmware #protocol #oled #release
What: Five new commands, all closing gaps where the editor could express something the board had no way to hear. **Present Keys** now renders on every screen type (the keycycle check sat inside the `is_layer` branch, so triggering it from a pomodoro screen set the flag and then drew the pomodoro screen over it), shows exactly one of icon / macro title / keycode in that priority, names the SCREEN ACTION a key runs on its own line, and owns the key field while up — white base, 2 Hz focused key, 4 Hz red event keys. **Icons became images**: PNG/SVG only, the text/emoji field deleted outright, rasterised host-side to a 32×32 1-bit mask (`0x5F`) thresholded on *alpha* rather than luminance, because icons are dark artwork on a transparent ground and a brightness threshold renders most of them blank. A mask rather than pixels: 2.6 KB for 21 keys against 43 KB, to render artwork a 128px amber panel cannot show off anyway. **Per-screen LED profiles** (`0x5E`) — the app always had them, the board had exactly one, so an animation set on one screen ran on all of them once you rotated away; not fixable host-side, since the encoder changes screens with no app involved. **Font** (`0x60`): the picker moved the app's preview and nothing else, and the board drew every title at a hardcoded scale 2. The board has ONE font, so a scale is the whole of what a font picker can mean there — and the app's character limits were fiction, accepting 16-char titles the panel then ran off the right edge. Limits are derived now: 128/(6·scale) = 21/10/7/5. **LED alerts**: countdown zero holds the whole board red until reset (an alarm you can miss is not one), a pomodoro phase change fires five rapid flashes; one mechanism for both, since they are the same signal at two durations.
**First shippable build.** The bundler had never run: `frontendDist` pointed at `../src`, so a release would have shipped unbundled source whose bare `@tauri-apps/api/core` import cannot resolve — it would have opened to nothing; `bundle.icon` was absent, so `tauri build` stopped at "Couldn't find a .ico icon"; and the icons were still the old KeyFigurator mark. Also fixed an alert that had holes in it: screen-event keys declare their border colour `!important`, so a plain inline style lost to it and the alarm skipped exactly the keys you would be looking at.
Refs: firmware keyboards/macro_pad_pro/{kf_hid.{h,c}, display.{h,c}, macro_pad_pro.c} (0.3.2→0.3.7); keyfigurator/src/{main.js, index.html, styles.css}, keyfigurator/src-tauri/{src/{kf_protocol.rs, model.rs, hid.rs}, tauri.conf.json, icons/}; release/Orbit-0.1.0-windows-x64.
